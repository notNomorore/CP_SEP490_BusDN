@startuml
title View Promotion Usage Statistics - Sequence Diagram

hide footbox
skinparam sequenceMessageAlign center
skinparam responseMessageBelowArrow true
skinparam ParticipantPadding 25
skinparam BoxPadding 10

actor Admin
participant "Admin Web App" as AdminWebApp
participant "PromotionController" as PromotionController
participant "PromotionService" as PromotionService
participant "PromotionRepository" as PromotionRepository
database "Promotion Collection" as PromotionCollection
participant "TransactionRepository" as TransactionRepository
database "Transaction Collection" as TransactionCollection

note over TransactionRepository, TransactionCollection
Usage statistics are implemented with PromotionUsage collection.
It is shown as TransactionRepository/Transaction Collection because usage represents applied transaction effects.
end note

Admin -> AdminWebApp: 1: View promotion usage statistics
activate AdminWebApp
AdminWebApp -> PromotionController: 1.1: GET /api/admin/promotions/{id}/statistics
activate PromotionController
PromotionController -> PromotionService: 1.2: getPromotionStatistics(id, filters, admin)
activate PromotionService
PromotionService -> PromotionRepository: 1.3: find promotion by id
activate PromotionRepository
PromotionRepository -> PromotionCollection: 1.3.1: query promotion
activate PromotionCollection
PromotionCollection --> PromotionRepository: 1.3.2: promotion or null
deactivate PromotionCollection
PromotionRepository --> PromotionService: 1.3.3: promotion
deactivate PromotionRepository
PromotionService -> TransactionRepository: 1.4: aggregate PromotionUsage by date, route, payment method
activate TransactionRepository
TransactionRepository -> TransactionCollection: 1.4.1: aggregate applied usage records
activate TransactionCollection
TransactionCollection --> TransactionRepository: 1.4.2: usage summaries
deactivate TransactionCollection
TransactionRepository --> PromotionService: 1.4.3: redemption count, discounts, revenue impact
deactivate TransactionRepository

alt [promotion not found]
    PromotionService --> PromotionController: 1.5: promotion not found
    PromotionController --> AdminWebApp: 1.6: 404 Promotion not found
else [no usage data]
    PromotionService --> PromotionController: 1.5: statistics with zero redemptions
    PromotionController --> AdminWebApp: 1.6: 200 Empty usage statistics
else [usage data available]
    loop 1.5: Group usage by date, route, payment method
        PromotionService -> PromotionService: 1.5.1: build charts and redemption rate
        activate PromotionService
        PromotionService --> PromotionService: 1.5.2: grouped statistics
        deactivate PromotionService
    end
    PromotionService --> PromotionController: 1.6: promotion statistics response
    PromotionController --> AdminWebApp: 1.7: 200 Usage statistics
end
deactivate PromotionService
deactivate PromotionController
AdminWebApp --> Admin: 1.8: Display usage dashboard
deactivate AdminWebApp

@enduml
