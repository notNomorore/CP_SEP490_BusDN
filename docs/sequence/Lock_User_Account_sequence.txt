@startuml
title Lock User Account - Sequence Diagram

hide footbox
skinparam sequenceMessageAlign center
skinparam responseMessageBelowArrow true
skinparam ParticipantPadding 25
skinparam BoxPadding 10

actor Admin
participant "Admin Web App" as Web
participant "AdminController" as UserController
participant "AdminModel" as UserRepository
database "User Collection" as UserDB

note over UserController,UserRepository
Implemented as PATCH /api/admin/users/:userId/lock. It validates object id and blocks self-lock, but does not check already locked status before update.
end note

Admin -> Web: 1: Confirm lock user account
activate Web
Web -> UserController: 1.1: PATCH /api/admin/users/:userId/lock
activate UserController
UserController -> UserController: 1.2: validate userId and self-lock rule
alt [invalid user id or admin locks self]
    UserController --> Web: 1.3.1: 400 validation error
else [request can proceed]
    UserController -> UserRepository: 1.4: lockUserById(userId, reason, lockedUntil, actorId)
    activate UserRepository
    UserRepository -> UserDB: 1.4.1: findByIdAndUpdate status LOCKED and push activityReports
    activate UserDB
    UserDB --> UserRepository: 1.4.2: updated user or null
    deactivate UserDB
    UserRepository --> UserController: 1.5: updated user or null
    deactivate UserRepository
    alt [user not found]
        UserController --> Web: 1.6.1: 404 User account not found
    else [user locked]
        UserController --> Web: 1.6.2: 200 User account locked successfully
    end
end
deactivate UserController
Web --> Admin: 1.7: Show lock result and refresh list
deactivate Web
@enduml
