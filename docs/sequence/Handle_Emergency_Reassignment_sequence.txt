@startuml
title Handle Emergency Reassignment - Sequence Diagram

hide footbox
skinparam sequenceMessageAlign center
skinparam responseMessageBelowArrow true
skinparam ParticipantPadding 25
skinparam BoxPadding 10

actor Admin
participant "Admin Web App" as Web
participant "AdminController" as AssignmentController
participant "AdminModel" as AssignmentRepository
participant "OperationNotification" as NotificationRepository
database "TripSchedule Collection" as ScheduleDB
database "FleetBus Collection" as VehicleDB
database "DriverShiftAssignment Collection" as DriverAssignDB
database "AssistantShiftAssignment Collection" as AssistantAssignDB
database "OperationNotification Collection" as NotificationDB

note over AssignmentController,NotificationRepository
Emergency reassignment is implemented by PUT /api/admin/trip-schedules/:scheduleId with emergencyReason. It writes TripSchedule.emergencyHistory and creates OperationNotification.
end note

Admin -> Web: 1: Submit emergency replacement staff or vehicle
activate Web
Web -> AssignmentController: 1.1: PUT /api/admin/trip-schedules/:scheduleId with emergencyReason
activate AssignmentController
AssignmentController -> AssignmentRepository: 1.2: findTripScheduleById(scheduleId)
activate AssignmentRepository
AssignmentRepository -> ScheduleDB: 1.2.1: find affected schedule
activate ScheduleDB
ScheduleDB --> AssignmentRepository: 1.2.2: current schedule or null
deactivate ScheduleDB
AssignmentRepository --> AssignmentController: 1.3: current schedule
deactivate AssignmentRepository
alt [schedule not found]
    AssignmentController --> Web: 1.4.1: 404 Trip schedule not found
else [completed or cancelled]
    AssignmentController --> Web: 1.4.2: 409 schedule locked
else [emergency update allowed]
    AssignmentController -> AssignmentController: 1.5: normalize replacement payload and validate emergency reason
    opt [replacement vehicle selected]
        AssignmentController -> AssignmentRepository: 1.6.1: findBuses()
        activate AssignmentRepository
        AssignmentRepository -> VehicleDB: 1.6.2: check replacement vehicle status
        activate VehicleDB
        VehicleDB --> AssignmentRepository: 1.6.3: vehicle availability
        deactivate VehicleDB
        AssignmentRepository --> AssignmentController: 1.6.4: vehicle result
        deactivate AssignmentRepository
    end
    opt [replacement driver selected]
        AssignmentController -> AssignmentRepository: 1.7.1: findEligibleDriverShiftAssignment(payload)
        activate AssignmentRepository
        AssignmentRepository -> DriverAssignDB: 1.7.2: check replacement driver shift
        activate DriverAssignDB
        DriverAssignDB --> AssignmentRepository: 1.7.3: driver availability
        deactivate DriverAssignDB
        AssignmentRepository --> AssignmentController: 1.7.4: driver result
        deactivate AssignmentRepository
    end
    opt [replacement assistant selected]
        AssignmentController -> AssignmentRepository: 1.8.1: findEligibleAssistantShiftAssignment(payload)
        activate AssignmentRepository
        AssignmentRepository -> AssistantAssignDB: 1.8.2: check replacement assistant shift
        activate AssistantAssignDB
        AssistantAssignDB --> AssignmentRepository: 1.8.3: assistant availability
        deactivate AssistantAssignDB
        AssignmentRepository --> AssignmentController: 1.8.4: assistant result
        deactivate AssignmentRepository
    end
    AssignmentController -> AssignmentRepository: 1.9: findScheduleAssignmentConflicts(payload, scheduleId)
    activate AssignmentRepository
    AssignmentRepository -> ScheduleDB: 1.9.1: find conflicting schedules
    activate ScheduleDB
    ScheduleDB --> AssignmentRepository: 1.9.2: conflicts
    deactivate ScheduleDB
    AssignmentRepository --> AssignmentController: 1.10: conflict list
    deactivate AssignmentRepository
    alt [no replacement available or conflict detected]
        AssignmentController --> Web: 1.11.1: 409 reassignment error
    else [replacement available]
        AssignmentController -> AssignmentRepository: 1.12: updateTripScheduleById(payload, emergencyReason)
        activate AssignmentRepository
        AssignmentRepository -> ScheduleDB: 1.12.1: push emergencyHistory and save new assignment
        activate ScheduleDB
        ScheduleDB --> AssignmentRepository: 1.12.2: updated schedule
        deactivate ScheduleDB
        AssignmentRepository --> AssignmentController: 1.13: updated schedule
        deactivate AssignmentRepository
        AssignmentController -> NotificationRepository: 1.14: create emergency operation notification
        activate NotificationRepository
        NotificationRepository -> NotificationDB: 1.14.1: insert notification for affected staff
        activate NotificationDB
        NotificationDB --> NotificationRepository: 1.14.2: notification saved
        deactivate NotificationDB
        NotificationRepository --> AssignmentController: 1.15: notification created
        deactivate NotificationRepository
        AssignmentController --> Web: 1.16: 200 Emergency reassignment saved successfully
    end
end
deactivate AssignmentController
Web --> Admin: 1.17: Show updated emergency assignment
deactivate Web
@enduml
